# 新宿人流デモの設計とデータ仕様

## 今回の位置づけ

Grafana の標準 Geomap と、移動アニメーション・時間スクラブ・立体都市表示では、必要な描画と操作が異なります。まず `demos/shinjuku-flow/index.html` に独立した可視化を作りました。Grafana にカスタム JavaScript を埋め込む、未承認プラグインを導入する、外部サイトへ公開する、といった作業は行っていません。

既存の MCP・ダッシュボード管理はそのまま利用できます。このデモは `dashboards/` の Grafana JSON ではないため、`manage.py apply` の対象には登録しません。今後 Grafana と統合する際は、地図アプリのホスト先、リンク連携か埋め込みか、認証と CSP、利用可能なプラグインを確認してから実装します。

## ファイルと実行

| ファイル | 内容 |
|---|---|
| `demos/shinjuku-flow/index.html` | UI、模式地図、合成データ生成、時間管理、描画、CSV 保存。単体で動作 |
| `demos/shinjuku-flow/README.md` | 開き方、操作、合成データの前提 |
| `demos/shinjuku-flow/preview.png` | 確認済みの3D画面。合成データのみ |
| `scripts/verify-shinjuku.cjs` | Playwright による13項目の動作検証 |

描画は `requestAnimationFrame` を使用します。CSS サイズとデバイスピクセル比に追従し、地図は ResizeObserver で再計算します。アニメーション中も指標集計は約200ms間隔に抑えています。Canvas の立体表示は、回転・俯角・建物高さを持つ座標を平面へ投影する方式です。

ページは外部 API、地図タイル、CDN、Web フォントへアクセスしません。新しい依存パッケージ・通信許可・認証情報・有料サービスは不要です。HTTP サーバーも必須ではないため、既存の環境インストール／起動設定は変更しません。

## 時間と再現性

開始時刻は08:00 JST。1×、10×、60×、300×の速度で、1日をループ再生できます。時刻バーの操作は再生を停止します。「現在時刻へ」は時計の日本時間に同期して毎フレームの位置を計算します。実測のライブデータ購読は行いません。

歩行者・車両の経路、開始位置、速度は固定シードで生成します。シミュレーション時刻から移動距離を求め、折れ線上の位置を補間します。同じ条件の時刻へ戻ると同じ位置を再現します。車は車道、歩行者は車道と歩行路を使いますが、交差点では即時に方向転換します。車道上の歩行者表示も簡略モデルであり、歩道の実在や安全な通行を示しません。

## 今回の CSV

ボタンは、その時刻にアクティブな全エージェントを CSV として保存します。表示レイヤーやエリア強調による絞り込みは行いません。

| 列 | 意味 |
|---|---|
| `simulation_time_jst` | 合成シミュレーションの時刻。`HH:mm:ss`、日付なし |
| `agent_id` | `P-0001` / `CAR-0001` 等の合成 ID。実際の個人・車両ではない |
| `mode` | `pedestrian` / `vehicle` |
| `latitude`, `longitude` | 新宿駅付近を原点とするローカル平面から近似変換した緯度経度 |
| `speed_mps` | 設定速度。m/s |
| `route_id` | 説明用のルート分類。GIS の経路 ID ではない |
| `source` | 常に `synthetic` |

日付なしの合成時刻を、実データの取得日時として使わないでください。速度とルート分類は設定値です。CSV はローカルで生成され、外部送信しません。

## 実データへ育てる場合

将来の入力は描画処理から分離し、位置観測・経路形状・背景地図を別々に扱います。

- 位置観測：`observed_at`（UTC ISO 8601）、集計単位または匿名 ID、交通モード、WGS84 の緯度経度、観測速度、`source`、品質・遅延情報。実際の個人単位データを扱えるかは元データの利用条件で判断します。
- 経路形状：GeoJSON LineString 等。観測時刻間を補間し、欠損・古いデータは明示します。今の時刻だけから合成位置を計算する処理と置き換えます。
- 地図：実際の道路・建物フットプリント・高さを持つ、利用条件を確認したベクターデータやタイル。
- 地形：実測 DEM とそのライセンス・解像度・座標系・垂直基準を確認します。山岳地形を見たい場合は、新宿駅周辺より広い範囲が必要です。
- 接続：利用可能なデータ基盤に合わせ、API、定期取得、WebSocket 等を選びます。PostGIS 等で空間集計したエリア別指標は Grafana の集計ダッシュボードへ連携できます。

これらの外部データ・配信基盤・公開ホスティングは今回追加していません。サービス選定時に費用、認証、通信先、公開範囲を確認します。

## 検証の範囲

`npm run verify:shinjuku` は実際の Chromium で13項目を操作します。画面が表示されたことだけでなく、停止時に位置が変わらないこと、同一時刻へ戻すと同一位置になること、3D 投影で画面座標が変化すること、ダウンロードされた CSV と表示条件に整合性があることを確認します。

PC 幅と390px幅の画像を確認します。合成データだけの画面には認証情報が入りません。地理的な正確性、実測人流、実測交通、実標高は検証対象に含まれません。今回のモデルにはそのような実データがありません。
