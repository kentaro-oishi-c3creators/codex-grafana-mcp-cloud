# 設計と管理方針

## Git と Grafana の役割

Git は変更履歴とレビュー対象のダッシュボード定義を保持します。Grafana Cloud は実際に表示される保存済みダッシュボードを保持します。管理スクリプトが公式 MCP の `get_dashboard_by_uid` と `update_dashboard` を使って両者を橋渡しします。自動同期や自動デプロイは行いません。

変更の流れは `JSON 編集 → ローカル検証 → 差分確認 → MCP 反映 → 再取得 → ブラウザ確認 → Git レビュー` です。Grafana 上で先に編集した場合は、`export` して差分を取り込みます。

## 定義と環境を分ける

`dashboard.json` は Grafana v2 の dashboard spec だけを保存します。MCP の `meta`、API 応答ラッパー、環境の UID は含めません。データソースの `name` は `prometheus` などの論理名です。

環境ファイルは論理名を実際のデータソース UID に変換します。反映時には環境のダッシュボード UID を設定し、指定されたフォルダーに保存します。取得時には逆変換するので、別環境の UID が定義へ混ざりません。

ブラウザの検証条件は各ダッシュボードの `checks.json` に置きます。サンプルは表示タイトル、72 と 99.5、複数点の時系列を確認します。実データのダッシュボードでは、変動する数値を固定値チェックしないよう条件を設計してください。

## 対応範囲

現在の構造チェックと反映ツールは v2 の Panel + GridLayout に対応します。TabsLayout、RowsLayout、v1 などを追加する際は、対応する構造チェック・変換・テストを先に整えてください。

反映は全体 JSON を保存します。`plan` で差分をレビューし、Grafana 上の変更を取り込み忘れていないか確認します。`check` は UID・内部 ID・version を除いて、保存された定義と Git の定義を比較します。

## 履歴と秘密情報

Git は配置・クエリ・説明の変更履歴、Grafana は保存履歴を持ちます。クエリ結果・メトリクス履歴そのものは Git に入れません。トークン、ブラウザ認証状態、プロキシ認証は Git や検証画像へ保存しません。

`.local/` の画像と検証結果にはダッシュボードの情報が入るので、公開前に内容を確認してください。新規定義やクエリにも顧客情報などを埋め込まないようレビューします。
